## Sprint 11 — Физика: инерция при драге, коллизии, Liquid Glass, желейные рёбра — DONE
Фидбек пользователя: "при передвижении выглядит очень странно + при остановке объект может
растягиваться очень сильно и даже внутрь"; "добавь Liquid Glass, сохрани желейность"; "у стрелок не
хватает реактивности".

- [x] **Баг сквоша при драге найден и исправлен.** Причина: `whileHover`/`whileTap` на той же ноде,
      что и слой драг-инерции, остаются "прилипшими" на всю длительность реального перетаскивания —
      framer-motion ловит `pointerdown`/hover независимо от собственной drag-системы xyflow (та
      работает через `d3-drag`, отдельный механизм). Их декларативные scale/scaleX/scaleY
      компоновались поверх динамического сквоша от скорости мыши — отсюда "странная" тряска.
      Плюс старая формула считала растяжение отдельно по осям X/Y, не совпадая с реальным
      направлением диагонального движения. **Фикс:** `whileHover`/`whileTap` отключаются на время
      `dragging`; растяжение теперь — единый скаляр вдоль направления скорости (поворот на угол
      движения → `scaleX/scaleY` вдоль локальной оси → обратный поворот), с `clamp` **внутри**
      `useTransform` — визуальная инверсия невозможна математически, даже если пружина осседания
      перелетит через 0 (см. `StepNode.tsx`)
- [x] Коллизия (`collisionBus.ts`) стала направленной — соседа "толкает" в сторону, откуда пришла
      перетаскиваемая нода, через тот же `stretch`/`angle`
- [x] **Liquid Glass** — новые токены `--glass-bg`/`--glass-border`/`--glass-blur`/`--glass-shine`
      (все 3 места: light/dark-media/dark-data-theme), `Blob` получил `glass` проп
      (`backdrop-filter: blur() saturate()` + полупрозрачный фон + стеклянный ободок + диагональный
      блик вместо вертикального). Включено по умолчанию в `JellyPanel`, добавлено в строки списков
      (`ScenarioCard`/`RunHistoryRow`) и в шапку приложения (`position: sticky` + glass). Цветные
      желейные ноды/кнопки остались непрозрачными "мармеладными" — стекло только на "хромовых"
      поверхностях
- [x] `JellyEdge` — постоянная лёгкая "дышащая" пульсация толщины линии (не только у `RUNNING`),
      реакция на hover через `.react-flow__edge:hover` (CSS, не JS), и "натянутое" состояние
      (`data.nodeDragging`, см. `ScenarioGraph.onNodeDragStart/Stop`) — ребро, один конец которого
      сейчас тащат, ярче светится и пульсирует чаще
- [x] **Важная находка про автотестирование через браузер:** `d3-drag` (на котором построен
      node-drag в `@xyflow/system`) регистрирует `mousemove`/`mouseup` на `event.view`, а
      синтетический `new MouseEvent(...)` без явного `{view: window}` в опциях создаётся с
      `view: null` — `d3-drag` тихо не навешивает слушатели движения, драг визуально не происходит,
      без единой ошибки в консоли. Добавление `view: window` в конструктор `MouseEvent` полностью
      решает проблему. Актуально для любой будущей ручной/автоматизированной проверки
      xyflow-взаимодействий через `dispatchEvent` (в отличие от связывания рёбер через `XYHandle` —
      тому эта деталь была не нужна, отсюда и путаница в Sprint 4)

## Sprint 12 — Физика v2 (без поворотов), удаление рёбер, Liquid Glass везде — DONE
Фидбек после Sprint 11: "после перетаскивания объекты остаются сплющенными", "при медленной
скорости всё дёрганое", "нельзя удалить связь между объектами", "Liquid Glass надо везде добавить,
прям полный редизайн".

- [x] **Sprint 11 подход (поворот + нелинейный scale в двух вложенных слоях) заменён целиком** —
      не долечивался, переписан с нуля. Причина обеих проблем: `angle = atan2(vy, vx)` на низкой
      скорости шумит на уровне квантования пикселя (крошечные `dx`/`dy` — соотношение сигнал/шум
      никакое), а поворот на этот шумный угол давал видимую "дёрготню" даже при плавном медленном
      драге. `stiffness — dumping` пружины на возврате плюс неоднозначная комбинация
      `rotate`+`scaleX/scaleY`+`rotate(-angle)` на одном и том же элементе (framer-motion компонует
      их в собственный порядок, не факт что rotate→scale→rotate(-angle) в том виде, что был
      задуман) — оставляла ноду "залипшей" растянутой после отпускания в части случаев.
      **Новое решение (`StepNode.tsx`)** — без единого поворота: скорость сглаживается
      экспоненциальным средним (`VELOCITY_SMOOTHING = 0.75`, гасит покадровый пиксельный шум, не
      убивая отклик на резких движениях), `bias = (|vx|-|vy|)/(|vx|+|vy|)` определяет, какая ось
      растягивается, а какая сжимается — навстречу друг другу, поэтому `scaleX+scaleY` физически не
      могут одновременно уйти в разнос. Величина растяжения (`stretchMag`) умножается на этот же
      bias, поэтому шум в bias на низкой скорости давится малой величиной stretchMag — дёрготня
      исчезает сама. Отдельный `useTransform`-clamp (`SAFE_MIN_SCALE=0.6..SAFE_MAX_SCALE=1.5`) —
      защита от "залипания": даже если пружина осседания перелетит, видимый scale не выйдет за
      разумные пределы.
- [x] **Удаление связи между шагами.** Раньше — только `Backspace` на выделенном ребре (не
      обнаруживаемо). Теперь `JellyEdge` рендерит через `EdgeLabelRenderer` кнопку × в середине
      выбранного ребра, `useReactFlow().deleteElements({edges:[{id}]})` на клик — видно и работает.
      Найден и исправлен смежный баг: `motion.button` с ручным `style.transform` не работает —
      framer-motion сам управляет CSS `transform` (композирует из своих motion-values) и молча
      затирает любую заданную вручную строку на каждом кадре, поэтому кнопка "прилипала" к (0,0)
      вместо середины ребра. Фикс — позиционирование через `left`/`top` + framer-совместимые
      `x:'-50%', y:'-50%'` вместо сырой строки `transform`.
- [x] **Полный редизайн на Liquid Glass** — по запросу "добавь везде, полный редизайн от яблока +
      желе". Раньше стекло было только на "хромовых" панелях; теперь **везде**, где раньше был
      сплошной цвет: `JellyButton` (полупрозрачный цветной тон + `backdrop-filter` + диагональный
      блик вместо кнопки-леденца), `StepNode` (JOB/QUEUE/QUEUE_CHECK — полупрозрачное цветное
      стекло, сквозь которое видна точечная сетка холста, цвет всё ещё чётко читается благодаря
      82%-й непрозрачности тона — `--glass-tint-pct`), `JellyBadge`/`StepNodeBadge`, тосты,
      `JellyInput`/`JellySelect`/`JellyTextarea` (стали "утопленными стеклянными лунками" — inset
      тень вместо плоской заливки), `JellyToggle`/`JellySegmented`, кнопки-крестики
      (`kv-list-remove`, `qc-key-remove`), контролы холста
      (`.react-flow__controls`), лого в шапке. Новые токены `--glass-tint-blur` (14px — лёгкое
      размытие для компактных элементов, тяжёлый `--glass-blur: 22px` остаётся только для больших
      панелей) и `--glass-tint-pct` (82% — доля цвета поверх прозрачности, чтобы не превращалось в
      блёклую пастель).

## Sprint 14 — Настоящая причина "залипания" ноды найдена и устранена — DONE
Фидбек: "объекты после перемещения всё равно остаются сплюснутыми" — Sprint 11 и 12 не долечили
проблему до конца, потому что чинили не ту причину.

- [x] **Найден фактический источник бага: `whileHover`/`whileTap` (декларативные пропы
      framer-motion) — вторая, независимая от моей, жестовая система на том же элементе.**
      framer сам слушает `pointerenter`/`pointerdown` НЕЗАВИСИМО от `d3-drag`, на котором построен
      node-drag в `@xyflow/system`. В первые несколько пикселей реального перетаскивания `dragging`
      из `NodeProps` ещё `false` (d3-drag не объявил жест драгом), поэтому `whileTap` успевает
      включиться (`scaleX:1.1, scaleY:0.88`); когда `dragging` тут же становится `true` и проп
      `whileTap` исчезает (`dragging ? undefined : {...}`), framer не всегда корректно "отпускает"
      уже запущенную tap-анимацию — нода залипает ровно в её значении навсегда. Ни Sprint 11, ни
      Sprint 12 эту причину не трогали (чинили только МОЮ анимацию инерции, а не конфликт с этой
      второй системой) — отсюда рецидив после, казалось бы, полного переписывания физики.

## Открытые риски
- **End-to-end прогон против реального бэкенда не подтверждён в этой сессии.** Postgres
  (`postgresql-x64-16`) на машине разработки был остановлен, запуск службы требует прав
  администратора, которых не было у агента. Само приложение (компиляция, все три экрана, error
  handling, drag-n-drop, конфиг-панели) проверено вживую в браузере при недоступном бэкенде —
  полный цикл save→run→live-мониторинг→stop→cleanup нужно пройти отдельно, когда бэкенд поднят.
- ~~Соединение рёбер (`onConnect`) и перетаскивание нод в браузерной автоматизации не
  воспроизводились штатным drag-инструментом~~ — разобрано в Sprint 11: причина в `event.view`
  синтетических `MouseEvent`, не в коде приложения. `onConnect`/`onNodeDrag` — стандартные хуки
  `@xyflow/react`, оба подтверждены живым взаимодействием (drag ноды с растяжением, соединение
  рёбер, коллизия) после фикса тестового скрипта.
- **`npm run dev`/`build` предупреждают про размер бандла** (~760 KB минифицированного JS,
  `@xyflow/react` + `framer-motion` — основной вес). Не блокер для внутреннего инструмента, но
  если появится необходимость — code-splitting через `React.lazy` по роутам (`ScenarioEditorPage`/
  `RunMonitorPage` тяжелее списка).
- **Проверка на среднем экране (< 1280px) не проводилась** — `resize_window` в этой сессии
  использовался только для смены темы, не для сужения вьюпорта. Хедер/тулбары используют flex без
  жёстких `min-width`, холст скроллится сам через `@xyflow/react`, но это не проверено вживую на
  реальном 1024px-экране.
- **Node 20.16.0 на машине разработки — ниже минимально заявленного рядом пакетов** (`vite@8`,
  `oxlint@1.81`, `nanoid@6` требуют Node ≥20.19/22) — отсюда и даунгрейд Vite/nanoid. Если на
  другой машине окажется более новый Node, эти пины можно снять и обновиться на актуальные мажорные
  версии, но тогда стоит заново пройти Sprint 0 (сборка/линт могли вести себя иначе на "родных"
  версиях).
